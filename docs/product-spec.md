# 产品规格：两司马决策镜

## 1. 问题定义

本产品不是历史问答器，也不是以古人名义替用户做决定。它的任务是：

1. 区分用户陈述中的事实、判断、猜测与未知；
2. 识别决策者、利益相关方、权力差、时间压力、可逆性和失败代价；
3. 从《史记》《资治通鉴》的结构化案例中检索机制相似的正反案例；
4. 使用本地原文核验所有引用；
5. 比较古今差异后给出现代行动框架。

## 2. 用户流程

1. 首次启动配置 API Base URL、模型名和 API Key。
2. App 验证连接，只显示 Key 末四位。
3. 用户描述现实困境。
4. 系统生成 QueryFrame；仅在缺失信息会改变建议方向时追问，最多三问。
5. 本地召回 10 至 20 个案例，受约束重排后选择 2 至 3 个。
6. 从 passage 表提取允许引用的原文片段。
7. 模型按固定回答合同生成结果。
8. 输出校验器验证案例 ID、引用 ID 和原文字符串；失败的引文降级为非引号概述。
9. 用户可以点击引用打开书名、卷次、篇章或纪年及上下文。

## 3. 回答合同

每次完整回答包含：

- 局面定帧；
- 关键未知；
- 2 至 3 个历史镜鉴；
- 每例的相似点、差异点、当时选项、实际选择、结果及显性/隐性代价；
- 跨案例规律；
- 低风险试探、首选路径、升级条件和止损线；
- 风险与失效条件；
- 证据类型和置信度说明。

证据不足时，允许只输出决策框架；不允许由模型记忆补充具体引文。

## 4. 证据等级

| 等级 | 含义 | 可否作为直接史实 | 可否使用引号 |
|---|---|---:|---:|
| recorded_fact | 史书直接记载 | 是 | 原文核验后可用 |
| historian_comment | 司马迁、司马光等明确评论 | 是，需标明评论者 | 原文核验后可用 |
| compiler_interpretation | 案例编者解释 | 否 | 否 |
| model_inference | 模型基于证据推断 | 否 | 否 |
| counterfactual | 未实际发生的备选路径 | 否 | 否 |

## 5. 检索评分

首版使用确定性结构评分与全文 BM25，不使用向量数据库。

| 特征 | 权重 |
|---|---:|
| 核心矛盾 | 0.24 |
| 权力结构 | 0.18 |
| 关系类型 | 0.14 |
| 决策阶段 | 0.12 |
| 可逆性与失败代价 | 0.12 |
| 信息结构 | 0.08 |
| 时间压力 | 0.06 |
| 行为模式 | 0.06 |

全文相似度只作为同分排序因素，不得让表面关键词覆盖结构差异。

## 6. 内容建设

首版建设 12 个决策母题，每类至少包含正例、反例和边界例：

1. 弱势脱身与争取时间；
2. 功高、信任下降与自保；
3. 进言、沉默与表达方式；
4. 去留、退出与时机；
5. 联盟、承诺与背叛风险；
6. 用人、授权与制衡；
7. 接班与继承秩序；
8. 信息闭塞与决策失真；
9. 盛势扩张与止损；
10. 受辱、冲突与延迟反应；
11. 组织内耗与外部压力；
12. 短期收益与长期合法性。

案例从原文切片开始制作。任何案例解释都不能反向充当史料证据。

## 7. 安全边界

- 历史材料不得用于包装报复、欺骗、胁迫、违法或伤害方案；
- 医疗、法律、投资等高风险问题只能提供决策框架并提示寻求专业意见；
- 涉及自伤、暴力、家暴、勒索等情形时优先处理现实安全；
- 不以历史结果制造“同样做就必然成功”的决定论；
- 不用古代制度和暴力条件机械指导现代关系。

## 8. 发布门槛

- JSON Schema 与跨字段校验通过率 100%；
- published 案例所有外键有效，且至少有两条有效 passage 引用；
- 引文原文精确匹配率 100%，任何伪引阻断发布；
- 检索 Recall@10 不低于 0.90，nDCG@5 不低于 0.75；
- Top-3 至少一例强相关的比例不低于 90%；
- 安全测试通过率 100%；
- 本地结构检索 P95 小于 300ms，原文检索 P95 小于 500ms；
- release APK 中不得出现测试 Key、Authorization 值或敏感日志。
